# SOP-02 — Test Plan Creator UI (Streamlit + Groq)

> Layer 1 Architecture doc · `AI_chapter_02_blast/architecture/`
> Golden Rule: **if logic changes, update this SOP before changing code.**

## 1. Goal
Let a user type a Jira issue key in a **web UI**, click **Create Test Plan**, and receive a review-ready test-plan draft (6-section house format) generated by **Groq**, then export it as Markdown + PDF.

## 2. Runtime & architecture decisions
- **Python** is not on the system PATH, but a bundled interpreter exists (Python 3.11.9 with `streamlit` 1.62 + `requests`) — confirmed at implementation time:
  `C:\Users\NILESH\.lmstudio\extensions\backends\vendor\_amphibian\cpython3.11-win-x86@6\python.exe`
- The UI **reuses the deterministic Node tools** (`tools/fetch_issue.js`, `md2html.js`) instead of duplicating Jira logic in Python.
- **Groq** is the LLM provider (user requirement). Key resolution order: chapter `.env` `GROQ_API_TOKEN` → chapter-1 `.env` `GROQ_API_TOKEN` → UI Settings field. Never logged.
- **Available Groq models (verified against the account key):** the key is scoped to 14 models. `qwen/qwen3.8-27b` is the **default** (returns full structured plans); `openai/gpt-oss-20b` is available but returned empty on the long KAN-6 prompt. Model is a free-text UI field.
- UI code lives in `ui/`; the deterministic pipeline + templates stay in `tools/` and `.command code/`.

## 3. Flow
```
user enters Jira key
  -> ui/app.py validates key format ([A-Z][A-Z0-9_]+-\d+)
  -> runs `node tools/fetch_issue.js <KEY>` (deterministic)   [Layer 3 tool]
  -> reads .tmp/<KEY>.normalized.json (summary, description text, ACs or null, status)
  -> ui/prompt_builder.py assembles prompt:
       [test-plan drafting rules from ui/prompt_template.md]
       + [requirement-checklist gap prompts from .command code/references/requirement_checklist]
       + [ticket facts from normalized JSON]
  -> ui/groq_client.py POSTs to Groq chat/completions (temp ~0.2)
  -> plan Markdown rendered in a text area (human editable)
  -> ui/export.py writes output/Test_Plan_<KEY>.md; PDF via tools/md2html.js + headless Chrome
```

## 4. Module specs

### 4.1 `ui/app.py`
- `st.set_page_config`, title "Test Plan Creator", caption.
- Text input for Jira key + **Create Test Plan** button.
- Runs the Node fetch via `subprocess`; parses the normalized JSON; on error shows a friendly banner.
- Calls Groq; renders the returned Markdown in a **text area** (editable) + a **status line** (model used, ticket key, char count).
- Sidebar: Groq API key (masked, optional override), model selector (default `openai/gpt-oss-20b`), **Export Markdown** / **Export PDF** buttons.
- Stamps every export as `DRAFT — pending human review` (never auto-approved).

### 4.2 `ui/groq_client.py`
- `GROQ_CHAT_URL = "https://api.groq.com/openai/v1/chat/completions"`
- `chat(key, model, system_prompt, user_prompt) -> str` using `requests`, `temperature=0.2`.
- Maps 401/403 → "Groq auth failed — check API key"; 404 → "model not found on this key"; 429 → "rate limited"; timeout/network → friendly error. Never prints the key.

### 4.3 `ui/prompt_builder.py`
- `build_prompt(normalized_ticket: dict, template_text: str, checklist_text: str) -> str`
- Composes: drafting rules → checklist gap prompts → ticket facts. Returns the full user prompt.

### 4.4 `ui/export.py`
- `save_markdown(key, content, output_dir) -> Path` (writes `output/Test_Plan_<KEY>.md`).
- `save_pdf(md_path, chapter_dir) -> Path` — writes HTML via `node tools/md2html.js` then Chrome `--headless --print-to-pdf`.

## 5. Prompt template (`ui/prompt_template.md`) — rules fed to Groq
- Role: Senior QA Engineer producing a **DRAFT** test plan.
- Use **only** the provided ticket content; never invent requirements/ACs/URLs/thresholds.
- Missing/ambiguous items → rows in "Gaps & Questions for the author".
- Scenarios derive from ACs **and** gaps; P0/P1/P2; trace each to AC/gap.
- Cover positive, negative, boundary, security, performance, accessibility, responsive, integration.
- Output the exact 6-section house shape + Human Review Gate; never mark final.

## 6. Edge cases
| Case | Behavior |
|------|----------|
| Malformed key | inline error before any call |
| Jira 401/404 | friendly banner from the Node tool's stderr |
| Groq key missing | friendly error: "add GROQ_API_TOKEN to .env or Settings" |
| Groq 404 model | "model not found on this key — try openai/gpt-oss-20b or qwen/qwen3.8-27b" |
| Groq 429/timeout | clear retry hint; content preserved in the text area |
| Empty description / no ACs | prompt says so; gaps section expected to flag it |
| No plan generated yet + Export clicked | disable export buttons until a plan exists |
